# Finance 상세 사용법

`python run.py`로 실행하고 **http://localhost:8000/** 에서 사용합니다.

- **실적 리포트** (`/`): 실적 생성기·원문·완성본을 `earnings/`에 통합했습니다. 기존 보고서도 보관함에 표시합니다.
- **위클리** (`/weekly`): 기존 스크리너, 시장 Recap, 산업 분류, ETF 설정을 모았습니다. 기존 `/recap`, `/industries`, `/sector-etfs`, `/chart` 링크도 계속 작동합니다.
- **수출입 통계** (`/customs`): 관세청 대시보드를 통합했습니다. HS 2→4→6자리 품목 탐색, 월별 수출·수입 차트, YoY·QoQ, 상위 품목 순위, 관련 기업 추가·삭제, 데이터 업데이트를 사용할 수 있습니다.

프로그램 구조와 폴더 정리 근거는 [STRUCTURE.md](STRUCTURE.md)를 참고하세요. 실행에 필요한 코드와 기존 데이터는 모두 `finance/` 안에 있습니다.

### 수출입 통계

`finance` 서버 하나로 사용합니다. 수집 자료·관련 기업·메타데이터는 `customs_workspace/trade.db`에 저장합니다. 기존 DB와 관련 기업을 보존했으며 별도 원본 폴더가 필요하지 않습니다. DB가 없는 PC에서는 빈 화면으로 시작하고 **데이터 업데이트**로 수집할 수 있습니다.

서버 시작·화면 조회는 관세청 API를 호출하지 않습니다. **데이터 업데이트**를 누르면 기본 60개월 범위의 누락 월과 최신 가용 월을 수집합니다. 수집은 페이지를 이동해도 계속되며, 돌아오면 진행 상태를 표시합니다. 완료 후 **결과 새로고침**으로 반영합니다. 서버 재시작으로 중단되면 다시 실행해 누락 월을 채울 수 있습니다. QoQ는 월 자료를 분기별로 합산한 값으로, 아직 끝나지 않은 분기는 누적액 기준입니다.

HS 품목명은 `02_OA/통합 문서1.xlsx`에서 가져온 `data/customs_hs_names.json`을 우선합니다. 코드의 앞자리 0을 유지하고 2·4·6·10자리 명칭을 저장합니다. 표·순위·툴팁·탐색 경로·상세 제목과 정적 내보내기에 같은 명칭을 사용하며, 명칭표에 없는 코드만 기존 API 대표명으로 표시합니다. 원본 엑셀과 수출입 원자료의 품목명은 수정하지 않습니다. 명칭표 갱신: `python scripts/import_customs_names.py` 실행 후 서버를 다시 시작합니다.

HS 2·4·6자리 목록은 모두 `HS코드 / 품목명 / 수출 / 수입 / 무역수지 / 수출 YoY / 수출 QoQ / 수입 YoY / 수입 QoQ`의 같은 형식을 사용합니다. 증감률 열도 클릭하여 정렬할 수 있습니다. YoY는 표시 기준월과 전년동월, QoQ는 표시 기준월까지의 분기 누적액과 바로 전 분기의 합계를 비교합니다. 비교 자료가 없거나 기준값이 0이면 `-`를 표시합니다. 정적 HTML에도 같은 계산을 적용합니다.

API 키는 `CUSTOMS_API_KEY` 환경변수 또는 `finance/.env`에 설정합니다. 폴더 정리 시 기존 로컬 키를 `finance/.env`로 이전했습니다. 설정 우선순위는 Finance `customs.api_key` → 환경변수 → Finance `.env`입니다. `.env`와 `customs_workspace/`는 Git에서 제외합니다. 다른 DB를 처음 가져올 때만 `customs.source_dir`를 명시하면 해당 폴더의 설정·키·DB를 초기 가져오기 원본으로 사용할 수 있으며, 기존 Finance DB는 덮어쓰지 않습니다.

```yaml
# finance/config.yaml의 선택 설정 (상대 경로는 finance 기준)
customs:
  db_path: customs_workspace/trade.db
  months: 60
```

CLI 수집: `python run.py --collect-customs` — 정적 내보내기: `python run.py --customs-static --no-open` (`output/customs.html`, 서버 없이 열람, 관련 기업 편집 비활성화, HS 6자리 상세 차트 제외).

수출입 회귀 검증: `python tests/check_customs.py` — 임시 DB와 모의 API로 원본 보존, 집계·드릴다운, 관련 기업 저장, 키 설정, 증분 수집·실패 복구, 정적 내보내기를 검사합니다. 실제 API는 호출하지 않습니다.

### 대시보드에서 실적 리포트 만들기

1. **새 리포트**에서 티커·회계연도·분기·회계 기준을 지정합니다.
2. **실적 표**에 회사명·통화·결산월·실제 보고 기간과 분기 매출·영업이익·EPS를 입력합니다. 완료된 연간 매출·영업이익은 선택 입력입니다. 기존 수치는 표에 미리 표시됩니다.
3. **컨퍼런스 콜**에 원문을 붙여 넣습니다. 없는 경우 비워 둡니다. 추가 메모는 선택 입력입니다.
4. **자료 저장** 또는 **리포트 생성**을 누릅니다. 생성할 때 변경한 자료도 저장합니다. 완성 리포트에서 PNG·HTML을 열거나 저장합니다.

완성 리포트는 **이번 분기 실적 → 과거 실적 추이 → 주가·밸류에이션 → 컨콜 주요 수치**의 네 부분으로 끝납니다. 가이던스·컨센서스 섹션과 컨센서스 입력은 제거했습니다. 이전에 저장한 원문과 완성본은 보존하며, 새 생성에는 기존 컨센서스가 전달되지 않습니다.

입력 자료는 파일에 보관합니다. 보고서를 전환할 때 변경 자료를 저장하고, 실패하거나 다른 탭의 수정과 충돌하면 전환을 중단합니다. 생성 중 페이지를 이동해도 작업은 계속되며 서버 재시작으로 중단되면 다시 실행할 수 있습니다.

금액은 선택한 통화의 **백만 단위**, EPS는 **주당 통화**입니다. 0은 `0`, 결측은 공란으로 입력합니다. 쉼표 숫자와 괄호 음수를 지원합니다. 엑셀 셀을 붙여 넣으면 선택 셀부터 오른쪽·아래로 채웁니다. 분기·연간 각각 최대 100행입니다. 중복 기간, 잘못된 숫자, 미래 예상치, 미완료 연간 실적은 저장하지 않습니다.

실적 입력·저장과 컨콜 없는 리포트 생성은 AI를 호출하지 않습니다. 컨콜을 제공했을 때만 설치·로그인된 Codex CLI가 원문을 정리합니다. 기본 모델은 `gpt-6-astra`, 추론 수준 high, 웹 검색 비활성화입니다. YoY·QoQ·영업이익률·PER은 고정 코드에서 계산합니다.

완성 PNG는 폭 2880px의 **한 페이지**이며 내용에 따라 높이가 늘어납니다. PER은 `주가 ÷ (해당 분기 EPS × 4)`입니다. EPS가 0 이하·결측이거나 통화 불일치·주식분할로 비교 기준이 달라지면 산출하지 않습니다. 주가와 최근 1년 추이는 Yahoo Finance, 시가총액은 Nasdaq/Naver를 조회하고, 실패하면 저장된 시장 자료와 가격 캐시를 사용합니다. 항목별 기준시점과 출처는 JSON·HTML에 보관합니다.

RIG의 `compact-review-v1`은 중복을 합친 컨콜 카드 최대 6개를 사용하며 주가 주변의 날짜·조회 설명과 차트의 일별 종가 문구를 PNG에서 숨깁니다.

설정은 `config.yaml`의 `earnings`에서 지정합니다. `source_dir` 기본값은 `earnings`, `model` 기본값은 `gpt-6-astra`, `timeout` 기본값은 1200초입니다. 입력 원문 이력은 `earnings/자료/<보고서>/dashboard/<버전>/`, 새 완성본은 `earnings/결과/<보고서>/dashboard/<버전>/`, 작업 기록과 시장 자료는 `earnings_workspace/`에 저장합니다.

저장된 완성본에 디자인만 다시 적용하려면 서버를 종료하고 `python scripts/refresh_earnings_reports.py --keep-market`를 실행합니다. 특정 보고서는 뒤에 `RIG_FY2026Q2`처럼 지정합니다. AI를 다시 호출하지 않고 이전 결과를 보존합니다. `--keep-market`를 생략하면 시장 자료도 다시 조회합니다.

## 📈 위클리 신고가 · 정배열 스크리너

한국(KOSPI/KOSDAQ) + 미국(S&P500/NASDAQ/NYSE) 전체 시장을 주간 기준으로 스캔하여
**신고가**와 **주봉 이동평균 정배열** 종목을 찾아 **필터 가능한 HTML 리포트**로 보여줍니다.

## 체크 조건

- **신고가 (고가 기준)**: 최근 주봉의 고가가 과거 N주 중 최고가인지
  - 4주 / 13주 / 26주 / 52주 각각 판정
- **정배열 (주봉 이동평균, 종가 기준)**: `MA4주 > MA13주 > MA26주 > MA52주` 로 내림차순이면 정배열

> 포함 기준(기본값 `any_high`): 4/13/26/52주 신고가 중 **하나라도** 충족하면 리포트에 포함.
> 리포트 안에서 신고가 조건·시장·정배열 여부를 **직접 필터링**할 수 있습니다.

## 설치

```bash
pip install -r requirements.txt
```

실적 PNG 생성에는 Node.js와 Python Pillow도 필요합니다. Pillow는 위 요구사항에 포함되며, 실적 생성기는 Node.js 기본 모듈만 사용하므로 별도 npm 패키지 설치는 필요하지 않습니다. 컨콜 요약과 Recap 코멘터리에는 설치·로그인된 Codex CLI를 사용합니다.

## 사용법

```bash
# 수집 없이 localhost 서버 실행 + 브라우저 자동 오픈
python3 run.py

# 특정 시장만
python3 run.py --markets KOSPI KOSDAQ

# 캐시 무시하고 새로 받기
python3 run.py --no-cache

# 서버 포트 지정 (기본 8000)
python3 run.py --port 8080

# 브라우저 자동 오픈 끄기
python3 run.py --no-open

# 전주 금요일 기준 스캔 후 정적 HTML 파일만 생성 (섹터 입력/저장 불가)
python3 run.py --static
```

`python3 run.py` 를 실행하면 데이터 수집 없이 **localhost 웹서버**가 바로 뜨고 브라우저가
`http://localhost:8000` 을 엽니다. 화면의 **[업데이트]** 버튼을 누를 때만 종목을 스캔합니다.
기준일은 언제 누르든 **전주 금요일**입니다(예: 2026-10-13에 누르면 2026-10-09).
스캔은 서버에서 계속 진행되므로 기다리는 동안 페이지를 벗어났다가 돌아와도 진행 상태를 확인할 수 있습니다.
결과는 `screen_cache.json`에 저장되어 서버를 다시 켜도 표시됩니다.
이전에 저장한 결과의 기준일과 다음 업데이트 기준일은 화면에서 따로 확인할 수 있습니다.
종료하려면 터미널에서 `Ctrl+C`.

한 포트에서는 서버를 하나만 실행합니다. Windows에서도 포트를 독점하도록 하여 이전 서버와 새 서버가 동시에 같은 주소를 사용하는 문제를 막습니다. 종목 목록·주가 수집 실패, 기준 주의 가격 누락은 업데이트 실패로 표시하고 저장된 결과를 유지합니다. 정상적으로 종목을 검사했지만 조건 충족 종목이 없는 경우에만 `N종목 검사 완료 · 조건 충족 0종목`으로 표시합니다. 성공한 결과를 저장할 때 직전 결과는 `screen_cache.previous.json`에 보관합니다. 새 캐시가 손상되었거나 검사 근거 없이 비어 있으면 직전 결과를 읽습니다.

수집·빈 결과·이전 결과 보존·서버 중복 실행 검증: `python tests/check_screen.py`.

## 종목 4분할 차트

localhost 스크리너에서 종목 **코드 또는 종목명**을 클릭하면 새 탭에 **6개월·모두 일봉**의 기본 차트 구성이 열립니다. 차트는 `web/chart-assets/`의 캔들 렌더러와 지표를 사용하고, 스크리닝 기준일까지의 실제 OHLCV를 표시합니다. 차트별로 캔들/라인, 지표, 추세선, 화면 맞춤을 조작할 수 있습니다.

입력 섹터에 연결한 ETF와 SPY를 사용합니다. 기본 구성은 좌상단 **종목 캔들**, 우상단 **종목 / 섹터 ETF 라인·시작 100**, 좌하단 **섹터 ETF / SPY 라인·시작 100**, 우하단 **종목·섹터 ETF·SPY 비교·시작 100**입니다. 시작 기간은 180일 대신 달력 기준 6개월입니다.

각 차트에서 종목, `NYSE:V / AMEX:IPAY` 같은 비율식, 일봉·주봉·월봉·분기봉 주기, 비교 종목(최대 5개)과 비교 기준(시작 0% 또는 시작 100)을 따로 설정할 수 있습니다. 상단 시작·종료 날짜와 기간 바로가기는 네 차트에 공통으로 적용됩니다. 한 차트를 휠로 확대하거나 드래그해 이동하면 공통 기간이 갱신되고 나머지 차트도 같은 날짜 구간으로 이동합니다. 해당 날짜 구간에 봉이 없으면 차트에 안내가 표시됩니다. 비교 차트는 현재 보이는 구간의 첫 공통 시각을 기준으로 정규화합니다. 비교 종목이 없어도 차트별 세로축에서 **가격 / 시작 0% / 시작 100**을 선택할 수 있습니다. 단일 종목·ETF·비율식은 현재 표시 구간의 첫 유효 종가를 기준으로 변환하며 캔들/라인, 거래량, 지표, 추세선을 유지합니다. 비교 중에는 시작 0% 또는 시작 100을 사용합니다. 휠·드래그·기간 변경 후 세로축과 OHLC·툴팁도 새 기준으로 갱신됩니다. 캐시에 없는 종목은 기존 시세 공급자로 조회를 시도하며, 실패하면 오류를 표시합니다. 정적 HTML 파일에서는 차트 링크를 제공하지 않습니다.

차트 상단의 **이미지 복사 / PNG 저장** 버튼으로 현재 네 차트를 화면 디자인 그대로 고해상도 이미지로 내보낼 수 있습니다. 화면에 적용된 글꼴·색상·둥근 테두리·간격·종목 헤더·OHLC·거래량 표시와 각 차트의 실제 가로·세로 비율을 유지합니다. 설정 입력칸·조작 버튼·지표 메뉴·툴팁·마우스 십자선은 제외합니다. 캡처는 화면 크기에 맞춰 데스크톱의 2×2 또는 좁은 화면의 세로 배열을 유지하며, 별도의 800×420 축약 레이아웃으로 재구성하지 않습니다. 현재 테마, 표시 기간, 세로축, 지표, 완성된 추세선을 유지합니다. 차트 우측 상단의 중복 가격·기준 문구는 표시하지 않으며 가격은 우측 축에서 확인합니다.

## 차트 검색용 ETF

차트의 종목·비교 입력칸에서 주식과 ETF를 코드 또는 이름으로 검색할 수 있습니다. `IPAY`, `QQQ`, `KODEX 200`처럼 입력하거나 검색 결과를 선택하세요. ETF는 비율식과 비교 차트에도 사용할 수 있습니다. 기존 `AMEX:IPAY` 입력은 DB에 등록된 실제 거래소 `ARCA:IPAY`로 연결됩니다.

- 검색 목록: `instruments.sqlite3`에 종목 코드·이름·국가·거래소·주식/ETF 구분을 저장합니다. 기본 미국 ETF 20개와 한국 ETF 3개를 등록하고, 기존 주식 캐시의 코드, 저장된 신고가 결과의 이름, 이후 스캔의 전체 주식 목록도 검색 DB에 등록합니다.
- 전체 ETF 목록: 차트 상단 **ETF 목록 업데이트** 또는 `python run.py --sync-etfs`로 미국(Nasdaq 공식 종목 목록)·한국(네이버 ETF 목록)의 ETF 정보를 갱신합니다. 목록 갱신은 시세를 일괄 다운로드하지 않습니다. 공급자 연결 실패 시 기존 DB를 유지하고 실패 상태를 표시합니다.
- ETF 시세: 해당 ETF를 차트에서 열 때 조회하며 `chart_cache/etf/US`, `chart_cache/etf/KR`에 저장합니다. 차트에서 추가 조회한 주식은 `chart_cache/stock/`에 저장합니다. 기존 주식 `cache/`는 계속 사용합니다.
- **신고가·정배열 스크리너에는 ETF를 포함하지 않습니다.** 수집 목록과 DB의 종목 구분을 확인해 시세 다운로드 전에 ETF를 제외하고, 저장된 결과를 표시할 때도 ETF를 제외합니다. `config.yaml`의 `markets`에 ETF 시장을 추가할 필요가 없습니다.
- 검색 DB에 ETF 정보가 있어도 최초 시세 조회는 공급자 연결이 필요합니다. 시세 조회 실패를 빈 차트의 성공으로 처리하지 않습니다.

## 섹터 ETF 연결과 차트 기본 구성

스크리너 또는 차트의 **섹터 ETF 설정**에서 입력 섹터별 ETF를 변경·추가할 수 있습니다. 초기 연결은 반도체 → SMH, 결제 → IPAY와 주요 섹터 ETF이며, S&P500 기준 ETF의 기본값은 SPY입니다. 종목에서 설정 화면을 열면 그 종목의 입력 섹터도 함께 수정할 수 있습니다. 저장 내용은 `sector_etfs.json`과 기존 `sectors.json`에 유지됩니다.

섹터를 입력하지 않았거나 ETF 연결이 비어 있으면 해당 비율·비교 차트에 설정 안내를 표시합니다. 미국 DB 주식은 저장된 자동 분류를 사용하며, 수동 설정이 우선합니다. 한국 주식 자동 분류는 아직 적용하지 않습니다. 저장 후 **이 구성으로 차트 열기** 또는 기존 차트의 **기본 구성 적용**으로 반영할 수 있습니다. 각 차트의 종목·봉 주기·세로축을 직접 바꾸는 기능도 유지됩니다. ETF 연결은 신고가 수집 대상을 늘리지 않습니다.

## 📊 주간 시장 Recap (`/recap`)

주요 글로벌 지수의 주간 성과를 한눈에 보여주고, **LLM API 비용 없이** 구독 중인
CLI(예: Codex)로 "Editor's Comment"를 자동 생성하는 페이지입니다.

서버 실행 후 **http://localhost:8000/recap** 접속 → **[🔄 업데이트]** 버튼 클릭 시
전주 금요일까지의 데이터로 갱신합니다. Recap도 서버 시작 시 자동 수집하지 않습니다.

1. **주요 지수(1-1)** + **주요 원자재(1-2)** 는 FDR로,
   **국채 금리·환율(1-3)** 은 네이버 금융 공개 API(일별·키 불필요)로 수집
   (현재가, 1W/1M/3M/YTD 등락, 52주 고점 대비, 60일 추이 스파크라인)
   - 지수: 한국/미국/일본/중화권/인도/유럽/북미 등 글로벌 시총 상위 시장 (CSI300 제외)
   - 원자재: 귀금속(금·은·플래티넘·팔라듐)·산업금속(구리)·에너지(WTI·브렌트·천연가스·휘발유·난방유)·농산물(옥수수·밀·대두·대두유·커피·코코아·설탕·면화)
   - 국채 금리: 미국·한국·독일·영국·프랑스·일본·중국 각각 2년·10년, 총 14개 — 등락은 **bp**
   - 환율: 달러인덱스·원/달러·원/엔·원/유로·원/위안 — 등락은 **%**
   - ⚠️ 1-3은 네이버 금융 **비공식** API라 구조 변경 시 깨질 수 있음(재시도·graceful 처리됨). 개인/내부용 조회 권장.
2. `config.yaml`의 `recap.commentary_cmd` 로 **분야별 AI 코멘터리 3종**(지수 / 원자재 / 금리·환율)을
   각각 독립 생성 — 각 섹션 표 바로 아래에 표시
3. `recap_cache.json` 에 저장 → 서버 재시작/재접속 시에도 즉시 표시

페이지 상단 버튼으로 **스크리너(`/`) ↔ Recap(`/recap`)** 를 오갈 수 있습니다.
표의 왼쪽 그룹 열은 국기/아이콘 + 굵은 구분선으로 국가·카테고리를 또렷하게 구분합니다.

- **[데이터만]** 버튼: AI 코멘터리 없이 시세 표만 빠르게 새로고침
- 상승=빨강 / 하락=파랑(한국식) 색상 표기


새 표시 목록은 설정과 기존 캐시에 함께 반영합니다. CSI300과 미국 30년·한국 3년은 제외하며 새 2년물에는 다른 만기의 가격을 재사용하지 않습니다. 기존에 수집하지 않은 행은 **업데이트 필요**, 수집을 시도했지만 공급자가 값을 반환하지 않은 행은 **조회 실패**로 표시합니다. 목록 변경 시 이전 목록의 코멘터리를 재사용하지 않고 업데이트를 안내합니다.

추가 원자재 심볼은 [Yahoo 선물 목록](https://finance.yahoo.com/markets/commodities/?ltr=1)과 [대두유 시세](https://finance.yahoo.com/quote/ZL%3DF/), 국채 RIC는 공개 제공자 문서·시세를 확인했습니다. RIC가 유효하더라도 네이버 API에서 해당 시계열 제공 여부는 업데이트 시 확인합니다.

### Recap 화면 구성

종합 / 지수 / 원자재 / 금리·환율을 탭으로 전환합니다. 기본 첫 화면은 **종합**이며 왼쪽에 전체 시장 해석, 오른쪽에 대표 지표의 1W·1M 변화를 표시합니다. 대표 지표 카드에서 각 분야의 전체 목록으로 이동할 수 있습니다. 분야별 세 화면은 화면 높이에 맞춘 동일 크기의 칸을 사용하며, 데스크톱에서는 왼쪽에 시세 표, 오른쪽에 해당 분야 코멘터리를 함께 표시합니다. 국가·분류 라벨은 가로로 표시하고 표 행과 추이 차트의 높이를 일정하게 맞춥니다. 긴 코멘터리나 작은 화면에서 넘치는 내용은 칸 내부에서 스크롤할 수 있어 페이지 전체가 길어지지 않습니다. 좁은 화면에서는 코멘터리를 표 아래에 배치합니다. 선택한 탭은 새로고침 후에도 URL의 위치값으로 유지됩니다.

### 코멘터리 CLI 설정 (`config.yaml`의 `recap:` 섹션)

```yaml
recap:
  commentary_cmd: "codex exec --model gpt-6-astra -c model_reasoning_effort=high --skip-git-repo-check --sandbox read-only --color never {prompt}"
  commentary_timeout: 300  # 각 코멘터리 호출의 대기 한도(초)
  commentary_enabled: true
```

- 모델은 **gpt-6-astra**, 추론 수준은 **high**로 명시합니다. 구독 계정과 설치된 CLI가 해당 모델 사용을 지원해야 합니다. 명령 옵션은 [Codex CLI 공식 문서](https://learn.chatgpt.com/docs/developer-commands?surface=cli)를 참고하세요.
- 프롬프트는 항상 **표준입력(stdin)** 으로 전달합니다. `{prompt}`는 본문 대신 `-`로 치환됩니다.
- 코멘터리는 분야별 3회와 종합 1회, 총 4회 순차 생성하므로 몇 분이 걸릴 수 있습니다.
- CLI 설치나 모델 호출에 실패하면 시세 표는 표시하고 해당 코멘터리에 실패 사유를 표시합니다.
- 설정·프롬프트·화면 변경은 서버를 재시작한 뒤 **업데이트**를 눌러 적용합니다. 기존 캐시의 코멘터리는 새로 생성해야 내용이 바뀝니다.

### 코멘터리 해석 기준

프롬프트는 `screener/recap.py`의 `build_index_prompt`, `build_commodity_prompt`, `build_rate_fx_prompt`, `build_overview_prompt`에서 관리합니다.

| 코멘터리 | 입력 데이터 | 해석 초점 |
| --- | --- | --- |
| 지수 | 주식 지수만 | 주도 지수·지역, 상대성과, 단기와 중기 추세, 강세의 지수 간 확산 |
| 원자재 | 원자재만 | 품목·분류 간 동조와 괴리, 광범위한 움직임인지 특정 품목인지 |
| 금리·환율 | 국채 금리와 환율만 | 국가별 2년·10년의 방향과 장단기 스프레드, 달러와 원화의 상대 움직임 |
| 종합 | 네 자산군 전체 원자료 | 자산 간 일치·충돌, 가장 근거 있는 시장 해석, 확인·반증 조건 |

각 코멘터리는 **핵심 해석과 근거 → 추세와 엇갈린 신호 → 다음 주 확인·반증 조건**의 3문단으로 작성합니다. 수치를 모두 반복하지 않고 해석에 필요한 값만 선택하며, 실제 관측과 원인 가설을 구분합니다. 가격 자료에 없는 뉴스·정책 결정·자금 유입·변동성은 사실로 쓰지 않습니다.

금리 스프레드는 동일 기준일의 2년물과 10년물이 모두 있을 때만 계산합니다. 10년-2년 스프레드와 그 주간 변화는 bp로 제공합니다. 결측을 0으로 처리하지 않으며, 행마다 기준일을 전달해 다른 날짜의 관측을 동시에 발생한 것으로 단정하지 않도록 합니다. 종합은 앞서 생성한 코멘터리를 이어 붙이지 않고 전체 원자료를 독립적으로 해석합니다.

## 미국 종목 자동 분류

미국 DB의 주식 항목을 종목별로 섹터에 연결합니다. Nasdaq 공식 CSV의 섹터·업종을 사용하고, BlackRock/iShares IWV 공식 종목별 섹터, VanEck SMH·Amplify IPAY 공식 보유목록, S&P500 GICS 보조 표(Wikipedia)로 보완합니다. 운용사 섹터를 Nasdaq의 섹터보다 우선하며 반도체·결제 테마는 별도 그룹으로 연결합니다. 한국 종목과 ETF 자체는 분류 대상에서 제외합니다.

- 자동 결과와 원본 업종·출처·적용 방법·보류 이유는 `instruments.sqlite3`의 `sector_classifications` 테이블에 저장합니다.
- `sectors.json`의 수동 설정이 항상 우선합니다. 수동 공란은 자동 분류도 가립니다. **자동 분류로 복원**으로 해당 수동 설정을 해제합니다. ETF 연결만 바꾸면 종목을 수동 분류로 고정하지 않습니다.
- 스크리너와 차트 기본 구성은 같은 유효 섹터를 읽습니다. ETF는 `sector_etfs.json`의 사용자 설정으로 결정하므로 섹터별 ETF 변경이 자동 분류 종목에도 적용됩니다.
- **섹터 ETF 설정 → 미국 종목별 분류·검토 목록** (`/sector-classifications`)에서 코드·이름·업종·ETF 검색, 자동/수동/검토 필터, 출처 확인과 종목별 수정이 가능합니다.
- SPAC·우선주는 `instrument_exclusions.json` 기준으로 기업 DB·검토 목록·가격 수집에서 제외합니다. 워런트·권리·채권, 펀드·투자신탁, 원본에서 찾지 못한 코드와 업종이 애매한 경우는 기존 검토 기록을 보존합니다.
- SMH는 공식 보유종목과 반도체 업종, IPAY는 공식 보유목록과 코드가 일치하는 미국 종목에 적용합니다. 나머지는 주요 11개 섹터에 대응합니다. Nasdaq 업종 변환은 앱의 분류 규칙이며 공식 GICS 인증 분류가 아닙니다. 연결은 비교 기준이며 ETF 편입 여부를 보장하지 않습니다.

분류 원본은 `classification_sources/`, 출처와 파일 목록은 `manifest.json`, 종목별 결과와 요약은 `classification_reports/`에 저장합니다. 갱신된 원본과 manifest를 준비한 뒤 다음 명령으로 미국 DB만 다시 분류할 수 있습니다. 원본 조회일을 manifest에 기록하세요. 저장된 원본으로 재실행하면 최신 업종을 조회한 것으로 간주하지 않습니다. 신고가 스캔이나 시세 수집은 실행하지 않습니다.

```bash
python run.py --classify-us --classification-manifest classification_sources/manifest.json
```

## KUIM 산업 분류

스크리너와 /industries에서 KUIM의 대분류·중분류·소분류를 조회하고 기업별로 수정합니다. 산업 분류 원본은 KUIM_전체결과표.xlsx의 기업전체·산업분류 시트입니다. 상위 분류만 지정된 기업과 복수 사업을 원본 그대로 유지하며, 자동 분류 초안·사업 검토 상태·원본 행과 자료 출처를 함께 표시합니다. 산업 기반 테마 후보는 기업별 확정 테마로 가져오지 않습니다.

서버를 시작하면 참고 파일의 변경 여부를 확인해 data/industry_taxonomy.json과 data/industry_assignments.json을 갱신합니다. 수동 분류는 국가:종목코드를 키로 industry_overrides.json에 따로 저장되어 참고 파일을 다시 가져와도 유지됩니다. 화면의 ‘KUIM 원본으로 복원’으로 수동 지정을 해제할 수 있습니다. 기존 ETF 비교용 섹터와 ETF 설정은 별도로 유지합니다.

원본 확인: python scripts/import_kuim.py --inspect

분류 자료 다시 가져오기: python scripts/import_kuim.py --import

변경 검증: python tests/check_industry.py

### 기업별 사업 검토와 수집 제외

- 검토는 `/industries`의 기본 국가·종목코드 순서로 진행하며, 우선주·스팩을 빼고 실제 기업 수를 셉니다.
- 분류 범위는 본체 및 연결 지배기업의 실제 상업 사업입니다. 단순 관계기업 투자와 연구·시제품만으로 산업 노드를 추가하지 않습니다. 복수 사업은 복수 경로로 저장합니다.
- `classification_reports/industry-review-progress.json`에 마지막 검토 기업과 다음 시작점을 기록합니다. 회사별 판단과 공식 출처는 회차별 `reviews.json` 및 `report.html`에서 확인합니다. 조사 에이전트는 기업을 나눠 맡고, 최종 담당자 한 명이 기준을 통일해 저장합니다.
- KUIM 원본 마스터에 없는 분류는 `data/industry_taxonomy_extensions.json`에 따로 기록합니다. 원본을 재수입해도 확장 분류와 수동 분류는 별도로 유지됩니다. 현재 보완 항목은 PCB·패키지 기판 소재, 용접 재료, 산업용 섬유·부직포·로프, 제혁·피혁 소재, 산업용 고성능 유기섬유입니다.
- 우선주·스팩 제외 기록은 `instrument_exclusions.json`에 저장합니다. 목록 갱신, 캐시 재등록, 산업 목록, 일괄 가격 다운로드, 직접 차트 조회에 같은 정책을 적용합니다. ETF는 이 제외 정책의 대상이 아닙니다. 삭제 전 DB 및 검토 원장은 회차별 보고서 폴더에 백업합니다.
- 제외 정책은 날짜와 무관하게 계속 적용되므로 다음 주 업데이트에서도 제외 종목의 주가를 요청하지 않습니다. 과거 가격 캐시는 보존되며 이를 통해 기업 DB가 재생성되지 않습니다.
